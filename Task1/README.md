# Задание 1. Целевая архитектура и приоритизация проблем

Кейс «Будущее 2.0»: медицинская компания с собственным банком, все данные в DWH на SQL Server 2008, отчёты строятся часами, впереди подключение фармацевтики и производителя электроники. Задача спринта - «витрина данных» и архитектура, при которой новые направления не требуют доработок центрального DWH.

Архитектура через год - домены с собственными средами в облаке плюс общая платформа данных самообслуживания:

- **Витрина данных** - портал самообслуживания и semantic-слой. Сотрудник сам строит отчёты по своим правам, без SQL и без очереди к команде DWH.
- **Платформа данных** - ingestion через CDC и Kafka, lakehouse на S3 с Apache Iceberg, витрины доменов как дата-продукты с контрактом и каталог данных с lineage.
- **Домены**: финтех (существующие сервисы на Golang и Java и новая своя БД), клиники (новый портал сотрудников вместо PowerBuilder и новый сервис медицинских данных), ИИ-сервисы (существующая ML-платформа и новый feature store поверх обезличенных витрин).
- **Интеграция**: API-шлюз с контрактами для партнёров и брокер сообщений вместо ESB.
- **Легаси** (DWH, ESB, PowerBuilder, Power BI поверх DWH) выводится в течение года, данные мигрируются в lakehouse.

На диаграмме отмечены три ключевых бизнес-сценария: С1 - быстрая отчётность (минуты вместо часов), С2 - независимое развитие финтеха и ИИ, С3 - масштабирование новых направлений контрактом с платформой, без новой логики в DWH. Отдельно выделено ограничение: медицинские карты, истории болезней и результаты исследований в аналитику не идут - это требование бизнеса из описания.
