# Задание 2. Разделение архитектуры на домены

Диаграмма потоков данных: [DFD-domains.drawio](DFD-domains.drawio) (открывается в draw.io), картинка - [DFD-domains.png](DFD-domains.png). Нумерация процессов на ней соответствует доменам: 1.x - клиники, 2.x - финтех, 3.x - платформа данных, 4.x - ИИ, 5.x - партнёры, 6.x - витрина.

## 1. Границы доменов

Границы проведены по подразделениям компании из описания, а не по техническим слоям. Каждое подразделение само решает, как хранить и обрабатывать свои данные, а наружу отдаёт только дата-продукт с контрактом.

| Домен | Кто владеет | Что хранит у себя | Что публикует | Что потребляет |
|---|---|---|---|---|
| Клиники (медицинские данные) | Операционная команда клиник | Медкарты, визиты, результаты - D1 с пометкой PHI | Обезличенные срезы через процесс 1.2 в общую платформу | Подсказки моделей диагностики от ИИ-домена |
| Финтех-сервисы | Команда финтеха (банковская лицензия) | Операции, счета, кредиты - D2 | События платежей (CDC) и витрину финтеха D5 | Ничего из общих витрин для операций не берёт - регуляторные требования |
| ИИ-сервисы | Команда ML | Версии моделей и признаки - D7 | Подсказки диагностики для клиник | Витрину D6 без PHI как обучающие данные |
| Партнёры (фарма, электроника) | Команда интеграций | Сырьё партнёров - D3 | Данные по контрактам в платформу | Витрину партнёров D8 для своих отчётов |
| Платформа данных (общая служба) | Центральная команда данных | Lakehouse D4 и витрины D5-D8, каталог | Инфраструктуру приёма, сборки витрин и lineage | Изменения от всех доменов |
| Витрина данных | Продуктовая команда портала | Ничего своего - только кэш сессий | Отчёты по правам доступа | Витрины D5, D6, D8 |

Платформа данных и витрина - не бизнес-домены, а внутренние продукты самообслуживания: домены пользуются ими, не согласовывая каждый шаг с центральной командой.

## 2. Как диаграмма обеспечивает бизнес-сценарии

**Интеграция нового финтех-сервиса.** Новый сервис пишет свои события в процесс 3.1 и публикует данные через собственный процесс вида 2.3. Остальные домены узнают о новинке из каталога (3.3) и подключаются к витрине. Ни один поток не проходит через DWH, доработок ядра нет. На диаграмме это зелёный процесс 2.3 и поток «события финтеха».

**Использование ИИ для анализа медицинских данных.** PHI остаётся в домене клиник: единственный выход данных - процесс 1.2, который отдаёт обезличенные срезы. Модели обучаются на витрине D6 без PHI (процессы 4.1 и 3.2), результаты возвращаются клиникам через API (поток «подсказки диагностики»). Красная пунктирная стрелка на диаграмме отмечает запрет: из D1 в lakehouse данные не идут.

**Подключение фармацевтики и электроники.** Партнёр подписывает контракт с процессом 5.1, его данные попадают в D3 и далее в общую платформу. Для остальных доменов это просто ещё одна витрина D8.

## 3. Почему именно так: аргументы

- **Ускорение вывода продуктов.** Изменения внутри домена не требуют работы центральной команды: финтех релизит свой сервис, когда готов, а не когда освободится команда DWH. В кейсе это главная боль - бизнес-логика в DWH делает каждое изменение медленным.
- **Снижение зависимости от DWH.** Общий DWH остаётся только источником исторических данных на время миграции. Новые потоки через него не идут, поэтому его вывод не блокирует развитие направлений.
- **Отдельное развитие направлений.** У финтеха свой контур под требования банковской лицензии, у клиник - изоляция медицинских данных, у ИИ - своя среда обучения. Команды нанимают под свои задачи, стек домена выбирают сами (Python у ИИ, Golang и Java у финтеха).
- **Управляемость.** Каталог и lineage (3.3) называют владельца и происхождение среза. В кейсе владельцы не указаны, а в одном DWH смешаны клиенты, медкарты, финансы, персонал и инвентаризация.
- **Медицинские карты для аналитики не используются** - это прямое требование бизнеса, поэтому PHI-хранилище D1 вынесено в отдельный домен и физически не попадает в lakehouse.

## 4. Правила потоков на диаграмме

- Внешние субъекты и хранилища обмениваются данными только через процессы.
- У каждого хранилища есть и запись, и чтение.
- Операционные данные домена не записываются в хранилище другого домена. Общие аналитические данные читаются только из витрин платформы D5, D6 и D8.
- Поток «подсказки диагностики» - ответ сервиса ИИ в процесс клиник. Медкарта при этом из D1 не уходит.
