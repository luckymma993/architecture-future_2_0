# Задание 2. Разделение системы на домены и потоки данных

Кейс «Будущее 2.0»: данные всех направлений в одном DWH на SQL Server 2008, бизнес-логика внутри DWH, интеграции через ESB. Задача - домены, которые развиваются независимо, без внедрения новой логики в DWH.

Четыре домена по подразделениям из кейса: клиники, финтех, ИИ и будущие партнёры (фарма, электроника). Платформа данных и витрина - общие службы, не отдельные бизнесы. Домены публикуют дата-продукты с контрактом. Аналитический обмен идёт через платформу: приём изменений (CDC и события), lakehouse на S3 с Iceberg, витрины D5, D6 и D8, каталог с lineage. Подсказки диагностики сервис ИИ отдаёт в процесс клиник: это ответ модели, а не выгрузка медкарты.

Ключевое ограничение кейса отражено явно: медицинские карты и результаты исследований остаются в домене клиник и в lakehouse не переносятся - модели ИИ обучаются на витрине без PHI.

Три бизнес-сценария разобраны прямо на диаграмме: интеграция нового финтех-сервиса, ИИ-анализ медицинских данных, подключение фармацевтического партнёра.
