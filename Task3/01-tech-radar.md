# Задание 3. Технический радар

Диаграмма: [tech-radar.drawio](tech-radar.drawio), картинка - [tech-radar.png](tech-radar.png). Кольца и квадранты - по методологии из урока: Adopt (в проде, низкий риск), Trial (пилоты), Assess (изучаем), Hold (не использовать в новом, выводить). Движение показано за год: новые технологии приходят сразу в то кольцо, где они будут к концу года.

## Почему кольца именно такие

- **Adopt** сразу у облачной платформы и существующих языков: без облака нет масштабирования под сотни терабайт, а Golang, Java и Python уже несут продакшн-нагрузку.
- **Trial** у всего, что проверяется пилотами в течение года: lakehouse и Data Mesh идут с Trial на Adopt по итогам этапов роадмапа, когда витрины доменов выдержат нагрузку реальных отчётов.
- **Assess** на диаграмме пустой: показано состояние к концу года. Semantic-слой и Terraform начинают год в Assess. Semantic-слой выбирается на этапе 3 и к концу года доходит до Trial. Terraform обкатывается на этапе 0 и переходит в Trial вместе с первыми окружениями.
- **Hold** у легаси: SQL Server 2008, PowerBuilder, ESB Camel и Power BI поверх DWH выводятся по мере готовности витрин, к финальному состоянию года DWH перестаёт быть узким местом.

Радар пересматривается раз в полгода: драйверы движения - инженеры доменов, каждое перемещение сопровождается ADR (подход из урока).
